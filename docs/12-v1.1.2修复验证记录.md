## 三、本轮新发现阻断缺陷

### 🔴 同步后数据重复翻倍

- **现象**：B端同步后，每条记录被写入两次——早餐出现 2 条、9月房租出现 2 条、私密占位行出现 2 条；月度支出从正确的 ¥3,628 变成 ¥7,256（正好翻倍）。
- **复现步骤**：
  1. A端记 4 笔账（早餐128公开、护肤品800私密、房租3500公开归属小棠、私房钱3000小金库）
  2. A端同步 → B端清掉 `fc_transactions` + `fc_sync_last_pull`
  3. B端点"立即同步"
  4. 结果：B端交易数为 6（应为 3：2 公开 + 1 占位），月度支出 -¥7,256（应为 -¥3,628）
- **复现性**：清数据重同步后**稳定复现**，非偶发。
- **影响**：
  - 财务数据翻倍 → 月度统计错误 → 结算金额全部错误；
  - **阻断级**（财务类产品数据正确性红线）；
  - 阻塞结算跨端锁定、墓碑删除的后续验证（数据翻倍环境下结果不可信）。
- **疑似方向**（供后续排查参考）：
  - `js/sync.js` 的 `upsertLocalRecord` 可能未按 `id` 去重（直接 push 到数组而非覆盖同 id 记录）；
  - 或 `pullSince` 被重复调用（如 famOps 的 Promise.all 中每条记录处理了两次）；
  - 建议在 `upsertLocalRecord` 入口加日志，确认同一 id 是否被写入两次。
