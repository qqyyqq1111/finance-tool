## 三、本轮新发现阻断缺陷

### 🔴 同步后数据重复翻倍

- **现象**：B端同步后，每条记录被写入两次——早餐出现 2 条、9月房租出现 2 条、私密占位行出现 2 条；月度支出从正确的 ¥3,628 变成 ¥7,256（正好翻倍）。
- **复现步骤**：
  1. A端记 4 笔账（早餐128公开、护肤品800私密、房租3500公开归属小棠、私房钱3000小金库）
  2. A端同步 → B端清掉 `fc_transactions` + `fc_sync_last_pull`
  3. B端点"立即同步"
  4. 结果：B端交易数为 6（应为 3：2 公开 + 1 占位），月度支出 -¥7,256（应为 -¥3,628）
- **复现性**：清数据重同步后**稳定复现**，非偶发。
- **影响**：
  - 财务数据翻倍 → 月度统计错误 → 结算金额全部错误；
  - **阻断级**（财务类产品数据正确性红线）；
  - 阻塞结算跨端锁定、墓碑删除的后续验证（数据翻倍环境下结果不可信）。
- **疑似方向**（供后续排查参考）：
  - `js/sync.js` 的 `upsertLocalRecord` 可能未按 `id` 去重（直接 push 到数组而非覆盖同 id 记录）；
  - 或 `pullSince` 被重复调用（如 famOps 的 Promise.all 中每条记录处理了两次）；
  - 建议在 `upsertLocalRecord` 入口加日志，确认同一 id 是否被写入两次。

### 7.1 v1.1.3 修复内容

- **保存按钮防重入**：校验通过即禁用，杜绝连点产生双 id 记录导致对端数据翻倍（同步翻倍的真正根因）
- **upsertLocalRecord 按 id 去重**：pull 时同 id 记录覆盖而非追加（双保险）
- **设置上云**：settings 固定 entity_id='settings' + 白名单消毒（familyName/members/splitRule），修复家庭名不同步
- **本机态隔离**：pull 仅合并共享字段，currentViewer/tier/加密开关/口令/PIN 永不被云端覆盖
- **首次采纳**：加入者/换机恢复者 pull 到家庭设置时无条件采纳一次，防时间戳反向覆盖家庭名
- **加入家庭后自动触发一次同步**
- sync 单测 60→80，全套 181 通过

- 自动化浏览器环境中，`window.confirm()` 原生对话框被自动拒绝（返回 false），导致删除/确认结算操作看似"无反应"。覆盖 `window.confirm = function(){return true}` 后功能正常。**这不是产品 bug**，真实用户浏览器中 confirm 对话框正常弹出。
