## 一、立项背景与项目目的

### 1.1 问题定义

双人家庭（情侣/夫妻）财务管理存在四个无解难题，现有工具全部无法同时覆盖：

1. **隐私与透明无法平衡**：共管要求全部透明，但 88% 年轻情侣保留私人小金库（Bankrate/Fidelity），现有产品要么"全公开"（支付宝小荷包），要么"全私密"（独立账本），无中间态；
2. **双人对账繁琐**：自定义分摊、垫付核算全靠人工，71% 年轻情侣因财务问题吵架；
3. **数据云端强制上传**：全部竞品依赖云端存储，68% 用户担忧隐私泄露，圈子账本 2022 年停服加剧信任危机；
4. **储蓄无目标无激励**：78.3% 家庭不清楚非必要支出占比，记账行为难以坚持。

### 1.2 项目目的（双目标）

| 目标 | 说明 | 衡量标准 |
|------|------|---------|
| **① 个人自用** | 满足本人双人家庭财务标准化管理需求，真实可用 | 日常记账/对账/看板全流程替代手工 |
| **② 求职作品集** | 沉淀"市场调研→立项→设计→AI落地→迭代→复盘"全流程0-1作品 | 完整文档链 + 可运行产品 + Git全版本记录 |

**能力展示三主线**：AI Agent 落地（大模型垂直场景应用）+ B端标准化设计（多角色权限/规则引擎）+ SaaS 商业化设计（分层定价/ROI测算）。

## 二、市场机会

### 2.1 市场规模（TAM/SAM/SOM）

| 层级 | 规模 | 测算依据 | 可信度 |
|------|------|---------|--------|
| TAM | 记账软件市场 68亿元（2025），CAGR 22%+ | 艾瑞咨询 | ⭐⭐⭐⭐⭐ |
| 用户盘 | 记账APP用户 3.23亿，25-35岁占 63.7% | 艾瑞咨询 | ⭐⭐⭐⭐⭐ |
| SAM | 双人家庭可服务市场 ≈1500万人 | MRD B.3 推算 | ⭐⭐⭐☆ |
| SOM | 付费用户 15-30万/年，对应年收入 0.3-0.9亿元 | SAM × 付费率1-2% | ⭐⭐⭐☆ |

### 2.2 赛道空白（竞品分析核心结论）

**没有任何一款产品同时覆盖以下四项能力**（7竞品+1前车之鉴全量扫描验证）：

1. 交易级公私权限隔离（含小金库完全隐藏）——全行业空白；
2. 本地离线存储（数据不上云）——全行业空白；
3. 大模型 AI 自动化记账（OCR/Excel/自然语言）——新兴AI记账产品（一木记账、Cush）全部仅限单人；
4. 双人专属财务规则（工资归集+零用钱自动发放）——**行业唯一**。

### 2.3 机会窗口

- 头部产品（随手记等）以广告变现为核心，本地隐私存储与其商业模式**根本冲突**（无法收集数据做精准推送），跟进动力不足；
- 圈子账本停服留下的"云端信任真空"，正是本地隐私型产品的获客窗口；
- 预计 6 个月窗口期，需快速落地 MVP。

## 四、差异化优势与战略控制点

### 4.1 核心差异化：三层隐私架构（行业首创，本次立项最高优先级）

| 层级 | 名称 | 伴侣可见范围 | 适用场景 |
|------|------|------------|---------|
| Layer 1 | 公开 | 全部明细可见 | 房租、餐饮、旅行（默认） |
| Layer 2 | 单笔私密 | 知道"存在私密支出"，看不到内容 | 个人购物、礼物 |
| Layer 3 | 小金库完全隐藏 | **不知道该账户存在** | 私房钱、个人储蓄 |

> 设计依据：88% 年轻情侣保留私人小金库（Bankrate/Fidelity）。小金库是健康财务关系的必要组成部分，产品正面推广而非负面暗示。底层实现为"按查看人身份过滤数据视图"，这是与所有竞品"全公开/全私密"二元模式的本质区别。

### 4.2 四大战略控制点（不可替代壁垒）

1. **双人财务规则引擎**：三层隐私 + 自定义分摊比例 + 月度垫付自动核算 + 工资归集/零用钱发放——行业唯一；
2. **本地隐私混合AI**：全量数据本地存储+加密，仅AI解析场景临时联网且请求脱敏——行业唯一；
3. **正向激励体系**：储蓄目标进度、里程碑徽章、浮亏安抚——行业深度领先；
4. **保守型AI风控**：仅R2及以下低风险建议、AI解析失败手动修正兜底——合规安全边界清晰。

### 4.3 措辞规范（对外/对内分层）

对外（用户/营销）用"协作、默契、边界"；对内（产品/设计/面试）用"关系边界、财务关系"；**禁止**使用"关系修复、关系解决方案"等过重表述。

## 五、产品方案概要

### 5.1 产品形态

纯静态 Web 工具（HTML5 + Tailwind CSS v3 + vanilla JS），无后端、无数据库服务器，浏览器打开即用；日常功能完全离线，仅AI解析场景临时联网。v2.0 考虑 PWA 封装。

### 5.2 功能框架

```
双人家庭AI理财助手
├── 数据层（LocalStorage 封装：CRUD + 加密 + 版本迁移）
├── 记账模块（记一笔：金额/分类/归属人/隐私层级标记）
├── 三层隐私架构（查看人身份切换 + 数据视图过滤）     ← P0 核心
├── 分摊结算引擎（自定义比例 + 月度垫付核算 + 结算清单）← P0 核心
├── 工资归集规则（工资归集比例 + 零用钱自动发放）      ← P1
├── 仪表盘（本月收支/分类占比/双人对比/小金库余额）
├── 储蓄目标（目标进度 + 里程碑激励）                  ← v1.1
├── AI记账（Kimi：自然语言/OCR/Excel，失败降级本地规则）← v1.1
└── 设置（成员管理/分类管理/数据导入导出/加密开关）
```

### 5.3 商业化功能边界（v1.0 同步实现，模拟SaaS分层）

- **免费版**：单人手动记账 + 简易看板（无双人、无AI、无分摊、无小金库）；
- **家庭会员版**：全部双人功能（以本地"解锁开关"模拟，验证商业化分层设计能力）。

## 六、商业模型

| 层级 | 策略 | 定价 | 功能边界 |
|------|------|------|---------|
| 免费版 | 单人引流 | 免费 | 单人手动记账+简易看板 |
| 家庭会员 | 双人完整功能 | 200-300元/年 | 全部P0+P1+P2功能 |
| 增值模板 | 场景化收费 | 10-20元/个 | 30岁百万方案、房贷分摊表、育儿储备规划 |

**单用户年ARPU 200-300元，是传统记账广告模式（20-50元）的5-10倍**；付费率按 SaaS 工具 1-3% 区间取 1.5% 估算，SOM 年收入 0.3-0.9 亿元。定价对标：Notion/滴答清单付费率、鲨鱼记账"基础功能锁VIP"为负面案例（免费版必须保留完整单人手动记账）。

**中长期模拟商业目标**（12-24个月，非运营承诺）：付费用户10万、年营收2000-3000万、月活留存≥60%、毛利率≥70%、18个月收支平衡。

## 七、技术方案概要

### 7.1 架构

| 层级 | 选型 | 说明 |
|------|------|------|
| 前端 | HTML5 + Tailwind CSS v3（CDN）+ vanilla JS | 纯静态，零构建、零部署成本 |
| 存储 | LocalStorage + 加密（Web Crypto API 或 CryptoJS，开发时选型） | 全量本地，用户完全掌控数据 |
| AI | Kimi API（自然语言解析 → OCR → Excel 分步落地） | 仅AI场景临时联网，请求脱敏 |
| 降级 | 本地轻量规则引擎（正则/关键词分类） | 断网或未配置API key时可用 |
| 多端 | v1.0 同设备身份切换模拟双人；跨设备同步（WebRTC/P2P）规划中 | 不阻塞MVP |

### 7.2 关键技术决策

1. **AI解析三步校验**：AI解析 → 用户确认/修正 → 确认入库，避免错误数据污染账本；
2. **AI风控红线**：投资建议仅限R2及以下，附强制免责声明；
3. **数据版本字段**：LocalStorage 存储带 schema 版本号，支持后续无痛迁移；
4. **开源复用策略**：分摊结算算法（Splitwise 式债务简化）优先借鉴成熟开源实现，开发前完成开源调研（见 `08-开源参考项目调研.md`）。

## 十、风险评估与应对

| 风险 | 等级 | 应对 |
|------|------|------|
| 头部竞品跟进双人功能 | 中 | 抢6个月窗口；本地隐私与广告模式冲突，跟进动力不足 |
| 本地AI算力/离线受限 | 低 | 仅解析场景联网；AI失败降级本地规则+手动修正 |
| 付费转化低于预期 | 中 | 免费版保完整单人记账先"用起来"；访谈/A-B验证定价 |
| AI理财建议合规 | 低 | 仅R2及以下+强制免责声明+人工兜底 |

**项目特有风险补充**：①个人项目断更风险 → 以小批次快速交付对冲，每批次保持可运行状态；②LocalStorage 容量上限（约5-10MB）与浏览器清缓存丢数据风险 → 数据分表存储+一键导出Excel备份（v1.0 内建导出）。

## 十一、立项结论

**建议：批准立项，立即启动 v1.0 MVP 开发。**

核心理由：

1. **市场真实存在**：SAM 1500万精准用户，四项能力全行业空白，且有付费意愿数据支撑；
2. **窗口期明确**：头部竞品商业模式与本地隐私冲突，跟进动力不足，6个月窗口；
3. **成本为零**：纯静态+本地存储+个人投入，无资金风险；
4. **双目标可达成**：自用闭环（三层隐私+分摊结算为最小可用集）与作品集闭环（文档链+代码迭代全留存）均可在 v1.0 实现。

**下一步动作**：①按 `06-产品路线图` 启动批次①开发；②完成开源参考项目调研（`08-开源参考项目调研.md`）后动工；③开发完成后回填复盘报告。
