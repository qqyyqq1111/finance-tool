> **版本**：v1.2.0
> **日期**：2026-10-04

## 三、P0 功能详细设计

### 3.1 F1 储蓄目标看板

#### 3.1.1 入口与位置

- 看板页（📊）顶部新增"储蓄目标"卡片，位于月度汇总下方
- 设置页 → 储蓄目标 → 可编辑目标参数

#### 3.1.2 目标设置

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 目标金额 | 数字 | 1,000,000 | 总储蓄目标，支持手动修改 |
| 目标日期 | 日期 | 用户30岁生日 | 截止日期，支持手动修改 |
| 起始金额 | 数字 | 当前家庭结余 | 已存金额，默认取当前结余，可手动覆盖 |
| 起始日期 | 日期 | 今天 | 开始日期，用于计算进度 |

> 目标为**家庭共同目标**，两端同步。小金库不计入共同储蓄（隐私隔离）。

#### 3.1.3 进度展示（看板卡片）

```
┌─────────────────────────────────┐
│  🎯 储蓄目标                      │
│  ┌──────┐                       │
│  │ 进度环│  已存 ¥156,000       │
│  │ 15.6%│  目标 ¥1,000,000      │
│  └──────┘  剩余 3年2个月         │
│            每月需存 ¥22,400      │
│  [编辑目标]                       │
└─────────────────────────────────┘
```

- **进度环**：SVG 环形进度条，百分比居中
- **已存/目标**：金额对比
- **剩余时间**：目标日期 - 今天，按"X年X个月"显示
- **每月需存**：(目标金额 - 已存金额) / 剩余月数，自动测算

#### 3.1.4 攒钱方案推荐

基于当前收支情况，给出**三种攒钱方案**，用户可切换对比：

| 方案 | 每月需存 | 计算逻辑 | 适用场景 |
|------|---------|---------|---------|
| 🟢 稳健型 | 月均结余 × 80% | 保留20%弹性，不影响生活质量 | 不想太紧绷，稳步攒钱 |
| 🔵 目标型（默认） | (目标-已存)/剩余月数 | 刚好按期达成目标 | 想在目标日期前存够 |
| 🔴 激进型 | 月均结余 × 100% | 全力攒钱，压缩所有非必要支出 | 想提前达成目标 |

- 每种方案显示：每月需存金额、预计达成日期、储蓄率（每月存/月均收入）
- 默认选中"目标型"，点击其他方案可切换查看
- 如果当前月均结余 < 目标型每月需存，红色提示："按当前收入可能无法按期达成，试试稳健型方案或增加收入"
- 方案选择存入 LocalStorage，下次打开记住用户选择

> 月均结余 = 近3个月（收入-共同支出）平均值，不含小金库。

#### 3.1.5 闲置资金提示

- **触发条件**：共同账户当前余额 > 闲置阈值（默认 ¥10,000，可在设置页自定义）
- **提示位置**：储蓄目标卡片下方，黄色提示条
- **提示文案**："当前共同账户有 ¥XX,XXX 闲置资金，建议纳入储蓄计划，加速达成进度"
- **操作按钮**：「一键纳入」→ 弹窗输入金额（默认全部闲置金额）→ 确认后储蓄目标的"已存金额"增加对应数额
- **频率控制**：每月最多提示 2 次，用户关闭后本月不再提示
- **两端同步**：闲置阈值和已纳入金额两端同步

> "一键纳入"不是真实转账，只是将这笔钱标记为"已纳入储蓄计划"，更新储蓄进度。共同账户余额不变（本来就是家庭的钱），只是储蓄目标的已存金额增加。

#### 3.1.6 储蓄健康度评估

基于**储蓄率**（月均结余 / 月均收入）评估家庭储蓄健康度：

| 储蓄率 | 等级 | 文案 | 样式 |
|--------|------|------|------|
| ≥30% | 优秀 💪 | "储蓄率 XX%，攒钱能力很强，继续保持" | 绿色 |
| 20%-30% | 良好 | "储蓄率 XX%，处于健康区间" | 蓝色 |
| 10%-20% | 一般 | "储蓄率 XX%，还有提升空间，试试减少非必要支出" | 橙色 |
| <10% | 需改进 ⚠️ | "储蓄率 XX%，偏低，建议设定月度储蓄目标" | 红色 |

- 显示位置：储蓄目标卡片内，攒钱方案下方
- 月均收入/结余 = 近3个月平均值，不含小金库
- 点击健康度标签可查看详细拆解：收入构成、支出Top3分类、近3个月结余趋势
- 如果收入数据不足（记账<3个月），显示"记账数据不足，继续记账后可评估"

#### 3.1.7 里程碑激励

- 预设里程碑：10万、30万、50万、80万、100万（可在设置页自定义增删）
- 达成里程碑时：看板卡片显示 🎉 动画 + "恭喜达成第一个10万！"
- 里程碑记录：设置页 → 储蓄目标 → 里程碑历史，显示每个里程碑的达成时间
- 首次达成（10万）有特殊庆祝效果（全屏动画+鼓励文案）

#### 3.1.8 数据存储

- LocalStorage key：`finance_savings_goal`
- 云同步：纳入家庭设置同步（复用 v1.1.3 家庭设置云同步机制）
- 字段：
  - `targetAmount` 目标金额
  - `targetDate` 目标日期
  - `startAmount` 起始金额（含已纳入的闲置资金）
  - `startDate` 起始日期
  - `idleThreshold` 闲置资金阈值（默认10000）
  - `selectedPlan` 用户选择的方案（stable/target/aggressive）
  - `milestones[]` 里程碑列表（金额+达成时间）
  - `idleDismissedMonth` 本月是否已关闭闲置提示

#### 3.1.9 验收标准

- [ ] 看板页显示储蓄目标卡片，进度环百分比正确
- [ ] 三种攒钱方案切换正常，每月需存金额计算正确
- [ ] 当前月均结余不足时，红色提示无法按期达成
- [ ] 共同账户余额超阈值时，显示闲置资金提示条
- [ ] 「一键纳入」后储蓄目标已存金额增加，进度环更新
- [ ] 储蓄健康度根据储蓄率显示正确等级和文案
- [ ] 记账不足3个月时，健康度显示"数据不足"
- [ ] 达成里程碑时显示庆祝动画，里程碑历史记录正确

### 3.2 F16 视角锁 + 切换提示

#### 3.2.1 视角锁开关

- **入口**：设置页 → 隐私与安全 → "锁定当前身份视角"
- **开关默认**：关闭（可切换）
- **开启后**：
  - 顶部身份切换按钮隐藏或置灰
  - 点击置灰按钮时 toast："视角已锁定，如需切换请先到设置页解锁"
  - 结算页、明细页的身份切换入口同步禁用
- **解锁**：设置页关闭开关 → 输入口令（复用现有"身份切换锁"口令，如未设置则要求先设置）

#### 3.2.2 切换时隐私提示

- 每次切换视角时（无论是否开启视角锁），弹窗提示：

```
┌─────────────────────────────┐
│  切换到「小棠」视角           │
│                              │
│  切换后：                     │
│  ✅ 可看到对方的公开账目       │
│  🔒 对方私密账仅显示占位行     │
│  💰 对方小金库完全不可见       │
│                              │
│  [确认切换]    [取消]         │
└─────────────────────────────┘
```

- 弹窗可勾选"不再提示"（存入 LocalStorage）
- 设置页可重新开启提示

#### 3.2.3 验收标准

- [ ] 设置页有"锁定当前身份视角"开关
- [ ] 开启后身份切换按钮不可用，点击有提示
- [ ] 解锁需输入口令
- [ ] 切换视角时弹窗显示隐私边界说明
- [ ] 勾选"不再提示"后切换不弹窗
- [ ] 两端各自独立锁定状态（A锁了不影响B）

### 3.3 手机端体验优化

#### 3.3.1 输入法遮挡

- 所有输入框 focus 时，调用 `element.scrollIntoView({block: 'center'})`
- 记一笔页：金额输入框 focus 时，自动滚动到表单可见区域
- 注册/登录弹窗：输入框 focus 时，弹窗整体上移

#### 3.3.2 触摸区域

- 所有可点击元素（按钮、tab、列表项）最小触摸区域 **44×44px**
- 底部导航 tab 高度 ≥50px
- 记一笔 FAB 按钮直径 ≥56px
- 检查当前所有按钮是否有过小的情况，统一调整

#### 3.3.3 加载状态与防重复点击

- **同步按钮**：点击后显示"同步中..."+转圈，禁用按钮，完成后恢复
- **注册/登录按钮**：同上
- **保存按钮**（记一笔）：点击后禁用，保存成功后自动关闭表单
- **删除/确认结算**：点击后禁用，防止连点

#### 3.3.4 下拉刷新（可选，P2）

- 明细页支持下拉刷新，触发"立即同步"
- 实现：touchstart/touchmove/touchend 监听，下拉距离>80px 触发

#### 3.3.5 验收标准

- [ ] 记一笔页金额输入时，输入框不被输入法遮挡
- [ ] 注册弹窗输入时，弹窗可见
- [ ] 所有按钮触摸区域≥44px
- [ ] 同步/注册/保存按钮点击后有 loading 状态，不能重复点击
- [ ] 快速连点保存只产生一条记录

## 四、P1 功能详细设计（视进度纳入，建议 v1.2 内完成 F4）

### 4.1 F4 支出预算与超支提醒

#### 4.1.1 功能定位

与 F1 储蓄目标形成"攒钱+花钱"双闭环：F1 管"该存多少"，F4 管"该花多少"。超支预警和优化建议帮助用户控制支出，间接提升储蓄率。

#### 4.1.2 预算设置

- **入口**：设置页 → 支出预算 → 分类预算列表
- **预置分类**：餐饮、交通、购物、娱乐、医疗、人情、房租/水电、其他
- **每个分类可设置**：
  - 月预算金额（数字输入，默认0=不设预算）
  - 预算周期：自然月（默认）/ 自定义周期（P2）
- **快捷设置**：
  - "基于上月支出一键填充"（上月各分类支出 × 0.9 作为预算建议）
  - "按比例分配总预算"（输入总预算，按历史支出比例自动分配到各分类）
- **预算为家庭共同预算**，两端同步。小金库支出不计入共同预算（隐私隔离）。

#### 4.1.3 预算执行看板

- **位置**：看板页，储蓄目标卡片下方，新增"本月预算"卡片
- **展示**：各分类预算进度条（已花/预算），按支出金额降序排列
- **进度条颜色**：
  - <60%：绿色（健康）
  - 60%-80%：蓝色（注意）
  - 80%-100%：橙色（接近超支）
  - >100%：红色（已超支）
- **每条显示**：分类图标、分类名、已花金额/预算金额、进度百分比
- **汇总行**：总预算、总已花、总剩余、整体执行率
- **点击某分类**：跳转到明细页并筛选该分类

```
┌─────────────────────────────────────┐
│  📊 本月预算                          │
│  总预算 ¥8,000 | 已花 ¥6,240 | 剩 ¥1,760 │
│                                     │
│  餐饮  ████████░░  ¥2,100/¥2,500  84% 🟠│
│  购物  ██████░░░░  ¥1,500/¥2,500  60% 🔵│
│  交通  ████░░░░░░    ¥640/¥1,000  64% 🔵│
│  娱乐  ██░░░░░░░░    ¥300/¥800    38% 🟢│
│  [管理预算]                           │
└─────────────────────────────────────┘
```

#### 4.1.4 超支预警（三级提醒）

| 级别 | 触发条件 | 提醒方式 | 文案示例 |
|------|---------|---------|---------|
| 🟡 接近超支 | 该分类已花 ≥ 预算的80% | 记一笔时输入框下方黄色提示 | "本月餐饮已花84%，还剩¥400" |
| 🔴 已超支 | 该分类已花 > 预算 | 记一笔时输入框下方红色提示 + 保存后toast | "本月餐饮已超支¥XXX，确认要记吗？" |
| ⚫ 严重超支 | 该分类已花 > 预算的150% | 看板页该分类标红 + 优化建议弹窗 | "餐饮超支50%，看看怎么优化？" |

- 记账时实时计算：输入金额后立即更新"如果记这笔，该分类将超支¥XXX"
- 超支时保存按钮不变红（不阻断记账），但保存后给 toast 提醒
- 每月1号自动重置预警状态

#### 4.1.5 优化建议（超支后给出具体建议）

当某分类超支时，在预算看板该分类旁显示「💡 优化建议」按钮，点击展开：

**建议生成逻辑**（基于规则，非AI）：

| 超支分类 | 分析维度 | 建议文案示例 |
|---------|---------|------------|
| 餐饮 | 外卖vs堂食占比、单笔均值 | "本月餐饮超支¥500，其中外卖占70%（单笔均值¥35），建议下月减少外卖次数，尝试自带午餐" |
| 购物 | 冲动消费（单笔<100且非必要分类占比） | "本月购物超支¥800，其中小额冲动消费（<¥100）占12笔，建议下月设'冷静期'，想买的东西先放购物车24小时" |
| 娱乐 | 频次vs单次消费 | "本月娱乐超支¥300，共8次外出，建议下月减少到4次，选择免费活动替代" |
| 交通 | 打车vs公共交通占比 | "本月交通超支¥200，打车占60%，建议非紧急情况选择公共交通" |
| 通用 | 与上月对比 | "本月支出比上月多¥XXX，主要增加在XX分类，关注一下" |

- 建议基于历史数据规则生成，不调用AI（保证离线可用、响应快）
- 每条建议可点"知道了"关闭，本月不再提示该分类
- 设置页可关闭"优化建议"功能（极简模式）

#### 4.1.6 与 F1 储蓄目标的联动

- LocalStorage key：`finance_budget`
- 云同步：纳入家庭设置同步
- 字段：
  - `budgets`：{ category: amount } 各分类月预算
  - `totalBudget`：总预算（自动汇总，也可手动覆盖）

### 4.2 F8 月度收支趋势

#### 4.2.1 功能定位

当前看板只有单月截面数据，用户无法看到收支变化趋势。增加近6个月趋势图，帮助用户判断"储蓄是在进步还是退步"。

#### 4.2.2 图表展示

- **位置**：看板页，预算卡片下方，新增"收支趋势"卡片
- **图表类型**：折线图，两条线（收入🟢、支出🔴）
- **时间范围**：近6个月（含本月）
- **X轴**：月份（如"5月""6月"...）
- **Y轴**：金额，自动适配最大值
- **数据点**：每个月显示收入/支出的圆点，hover/点击显示具体金额
- **结余柱**：可选，在折线图下方用浅色柱状图显示每月结余（收入-支出）

```
近6个月收支趋势
  金额
  8000 |        ●支出
  6000 |  ●   / \   ●收入
  4000 | / \ /   \ /
  2000 |/   ●     ●
     0 +----------------
       5月 6月 7月 8月 9月 10月
```

#### 4.2.3 数据计算

- 每月收入 = 该月所有"收入"类型交易金额合计（不含小金库）
- 每月支出 = 该月所有"支出"类型交易金额合计（不含小金库、不含私密账内容但计入金额？—— 私密账支出应计入总支出，因为是真实花了的钱，只是对方看不到明细）
- 每月结余 = 收入 - 支出
- 本月数据实时更新（记一笔后图表刷新）
- 历史月份数据从 LocalStorage 读取（按交易记录的日期字段分组）

> 私密账处理：支出趋势图显示总支出金额（含私密账），因为趋势图只看金额不看明细，不泄露隐私。但对方视角下，私密账的明细仍不可见。

#### 4.2.4 交互

- **点击某个月的数据点**：跳转到明细页并切换到该月
- **切换收入/支出显示**：点击图例可隐藏/显示对应折线（默认都显示）
- **趋势总结文案**：图表上方显示一句话总结，如：
  - 近3个月结余持续增长："近3个月结余持续增长，攒钱趋势不错 📈"
  - 近3个月支出持续增长："近3个月支出持续增长，注意控制 📉"
  - 收支基本平稳："近6个月收支基本平稳"
- 数据不足（记账<2个月）：显示"记账数据不足，继续记账后可查看趋势"

#### 4.2.5 实现方案

- **优先方案**：原生 SVG 手绘折线图（零依赖、加载快、样式可控）
- **备选方案**：Chart.js CDN（如果原生SVG实现复杂，如tooltip、动画等）
- 动画：数据加载时折线从左到右绘制动画（CSS transition）
- 响应式：图表宽度100%，高度固定200px，移动端适配

#### 4.2.6 验收标准

- [ ] 看板页显示近6个月收支趋势折线图
- [ ] 收入线和支出线颜色区分，图例清晰

### 4.3 F11 同步冲突提示

#### 4.3.1 功能定位

当前云同步采用 LWW（Last Write Wins，最后写入优先）策略，两端同时修改同一笔记录时，后修改的覆盖先修改的，用户无感知。增加冲突提示，让用户知道"有更新已自动合并"，避免困惑。

#### 4.3.2 冲突检测逻辑

- **冲突场景**：本地和云端的同一笔记录（相同 id）都有修改，且本地的 `updated_at` < 云端的 `updated_at`（云端更新）
- **检测时机**：同步时拉取云端数据后，逐笔对比
- **冲突类型**：
  - 同一笔记录金额/备注被修改
  - 同一笔记录被删除（墓碑删除）
  - 同一笔记录隐私级别被修改

#### 4.3.3 提示方式

| 冲突数量 | 提示方式 | 文案 |
|---------|---------|------|
| 1-2笔 | toast 提示（3秒后自动消失） | "有2笔记录已更新，已自动同步" |
| 3笔以上 | 通知条（可关闭） | "有X笔记录已从伴侣设备同步，点击查看" |
| 涉及删除 | toast 特别提示 | "伴侣删除了X笔记录，已同步" |

- 提示不阻断流程，自动采用 LWW 结果
- 通知条点击可展开冲突列表（P2 高级功能，v1.2 只做提示）
- 提示频率控制：同一批次同步只提示一次，不每笔都弹

#### 4.3.4 冲突记录（P2 预留）

- LocalStorage 记录最近10次冲突：{ id, 本地修改内容, 云端修改内容, 采用版本, 时间 }
- 设置页 → 同步日志 → 可查看历史冲突
- v1.2 只做提示，冲突列表和"选择保留哪版"作为 P2 延后

#### 4.3.5 验收标准

- [ ] 两端同时修改同一笔记录后，同步时显示 toast 提示
- [ ] 提示文案包含更新笔数
- 伴侣删除记录后同步，提示"已删除X笔"
- [ ] 同一批次同步只提示一次
- [ ] 提示3秒后自动消失，不阻断操作
- [ ] 冲突记录正确采用 LWW 策略（后修改的生效）
