# v1.1 PRD — 跨设备双人同步（端到端加密）

> 版本：v1.1-draft1（2026-09-06）
> 定位：把 v1.0 的"单设备切换身份模拟双人"升级为"两人各一台手机、各自登录、端到端加密实时同步"的真双人产品。
> 范围红线：**v1.1 只做跨设备同步**；AI 拍照/语音/Excel 记账（F10）顺延 v1.2；F1-F9 功能建议池不进 v1.1。
> 上游文档：07-分模块PRD（v1.0 基线）、08-开源调研（License）、00 §5.5（F池）。

---

## 1. 目标与非目标

### 1.1 目标

1. 两人各用自己的手机（各自登录账号），记账后数据自动同步到对方设备。
2. **端到端加密**：云端（Supabase）只存密文，服务商无法读取任何账目内容；密钥永不落云端明文。
3. **三层隐私在同步下语义不变**：
   - 公开账（public）：双方同步互见、参与分摊；
   - 单笔私密（private）：同步到家庭空间但用**个人密钥**加密，对方设备拉到也解不开 → 表现为"对方有 1 笔私密记录"占位行；
   - 小金库（vault）：**不进家庭空间**，仅存个人私有空间（RLS 隔离），对方设备物理上拉不到 → 完全无痕；但本人换设备登录后可恢复。
4. 离线优先：断网照常记账，联网后后台自动同步；未登录/未配对时退化为 v1.0 纯本地模式，功能不残。
5. 免费/会员门控延续：跨设备同步是**家庭会员核心卖点**（免费版保持单机）。

### 1.2 非目标（v1.1 不做）

- 多人家庭（>2 人）、协作编辑同一笔账；
- 实时协同光标/在线状态（只需近实时，分钟级延迟可接受）；
- 服务端 AI、服务端报表（服务器看不到明文，算不了）；
- Web 端之外的原生 App（PWA 封装留 v2.x）。

## 2. 总体架构

```
┌─────────────────────┐        ┌─────────────────────┐
│  手机A（小棠）        │        │  手机B（阿晨）        │
│  LocalStorage(明文)  │        │  LocalStorage(明文)  │
│   ↓ 加密 ↓            │        │   ↓ 加密 ↓            │
│  familyKey 解公开账   │        │  familyKey 解公开账   │
│  personalKey 解私密  │        │  personalKey 解私密  │
└─────────┬───────────┘        └──────────┬──────────┘
          │  密文（AES-GCM-256）           │
          └──────────┬────────────────────┘
                     ↓
        ┌────────────────────────────┐
        │  Supabase（云端只见密文）      │
        │  auth（邮箱账号）              │
        │  families / family_members   │
        │  invites（一次性邀请码）        │
        │  family_docs（公开+私密密文）   │
        │  personal_docs（小金库密文，RLS）│
        └────────────────────────────┘
```

- 技术栈延续：纯静态 HTML5 + Tailwind CDN + vanilla JS，新增 `@supabase/supabase-js`（CDN）。
- 加密复用 v1.0 `js/crypto.js`（WebCrypto AES-GCM-256 + PBKDF2 15 万次），新增密钥协商与同步引擎 `js/sync.js`。

## 3. 账号与家庭模型

### 3.1 账号（Supabase Auth）

- 注册方式：**邮箱 + 密码**（v1.1）；魔法链接/匿名体验留后续。
- 一个账号 = 一个自然人；一台设备登录一个账号（v1.0 的"同设备切换身份"保留为备用：设置里仍可切换查看视角，但主路径是各自登录）。
- 首次登录后：引导"创建家庭"或"输入邀请码加入家庭"。

### 3.2 家庭（family）

| 字段 | 说明 |
|------|------|
| id | uuid，创建时生成 |
| name_enc | 家庭名密文（familyKey 加密）；服务器连家庭名都看不到 |
| created_by / created_at | 创建者 uid / 时间 |

family_members：`family_id, user_id, member_id(m1/m2), display_name_enc, pubkey?, joined_at, status`。
v1.1 家庭固定 2 人，满 2 人后邀请码失效。

### 3.3 配对（邀请加入）流程

设计原则：**密钥不经服务器明文传输**，不引入公钥体系（降低复杂度），用一次性高熵邀请码。

1. 创建者 A 点"邀请伴侣"：
   - 本地生成 `familyKey`（32 字节随机，AES-GCM 用）；
   - 生成邀请码 `code`：**邀请链接**形式 `https://<pages>/#/join?c=<24字符随机secret>`（secret 在 URL fragment，不进服务器日志/不随 Referer 发送）；同时展示 8 位人类可读短码仅作辅助兜底（见 §9 风险）；
   - 云端写 invites：`{ family_id, enc_family_key, expires_at, used }`，其中 `enc_family_key = AES-GCM(key = PBKDF2(code), plaintext = familyKey)`；
   - A 通过微信/口头把链接（或短码）发给 B。
2. B 注册/登录后打开链接（或输短码）：
   - 前端用 code 派生密钥解密 `enc_family_key` 得到 familyKey，存入 B 本地（用 B 的登录口令派生密钥加密落 LocalStorage）；
   - 写 family_members（B 加入，member_id=m2），invites 标记 used（一次性，RLS/ RPC 保证）；
   - 首次全量拉取 family_docs 解密合并。
3. 邀请码 24 小时过期、用后即焚；输错 5 次锁定该码。

### 3.4 个人密钥（personalKey）

- 每人生成 32 字节随机 `personalKey`，用于加密自己的 private 账与 vault 账。
- **换设备恢复**：personalKey 用"本人登录口令派生密钥"（PBKDF2(password, personalSalt)）加密后存 personal_docs 一条特殊记录（`_key_backup`），RLS 仅本人可读 → 新设备登录后输口令解密恢复。
- familyKey 同样在本地用登录口令加密保存；换设备时若邀请码已失效，可由任一已加入设备"重新授权"（生成新 invite 给该账号）。

## 4. 三层隐私 × 加密存储矩阵

| 数据类型 | 加密密钥 | 云端位置 | 对方设备 | 本人换设备 |
|----------|---------|---------|---------|-----------|
| 公开账 public / 结算单 / 分类规则 / 家庭设置 | **familyKey** | family_docs | 可解密，互见 | 可恢复 |
| 单笔私密 private | **personalKey** | family_docs（能拉到密文） | 拉到但**解密失败 → 计为占位行**（"对方有 N 笔私密记录"） | 口令恢复 |
| 小金库 vault | **personalKey** | **personal_docs（RLS 仅本人）** | 物理上拉不到，完全无痕 | 口令恢复 |

- 占位行计数规则：family_docs 中 `enc_key = 'personal'` 且非本人上传的记录条数 = 对方私密笔数（含已软删墓碑，墓碑也计数口径沿用 v1.0：private 占位只表示"有"，不展示内容）。
- 统计口径沿用 v1.0：private/vault 不进对方统计与分摊；privacy.js 纯函数**输入改为解密后的本地数据**，过滤逻辑零改动。

## 5. 数据模型与本地 Schema v2

### 5.1 本地（LocalStorage）新增/变更字段

所有同步实体（transactions / settlements / categories / settings 中需同步部分）统一追加：

| 字段 | 说明 |
|------|------|
| `id` | v1.0 已有（uuid），同步主键 |
| `updatedAt` | 毫秒时间戳，每次写入更新（LWW 依据） |
| `deviceId` | 安装实例随机 id（tiebreak 用） |
| `deleted` | 软删墓碑标记（true=已删除，同步后双方物理清理） |
| `_sync` | `'dirty'`（本地改未传）/ `'clean'`（已同步） |

- schema 版本 1 → 2：启动迁移给存量记录补 `updatedAt=现有时间/createdAt`、`deviceId=本机`、`deleted=false`、`_sync='dirty'`（首次联网全量上传）。
- 金额仍以**分（整数）**存储，红线不变。

### 5.2 云端表（Supabase DDL 摘要，建表脚本随批次⑥提交）

```sql
families        (id uuid pk, name_enc text, created_by uuid, created_at timestamptz)
family_members  (family_id uuid, user_id uuid, member_id text, -- m1/m2
                 display_name_enc text, joined_at timestamptz,
                 primary key(family_id, user_id))
invites         (id uuid pk, family_id uuid, enc_family_key text,
                 code_hash text, short_code text, expires_at timestamptz,
                 used boolean, attempts int)
family_docs     (family_id uuid, entity_type text, entity_id uuid,
                 enc_payload text, enc_key text, -- 'family'|'personal'
                 owner_uid uuid, updated_at bigint, device_id text,
                 deleted boolean,
                 primary key(family_id, entity_type, entity_id))
personal_docs   (user_id uuid, entity_type text, entity_id uuid,
                 enc_payload text, updated_at bigint, device_id text,
                 deleted boolean,
                 primary key(user_id, entity_type, entity_id))
```

RLS 要点：
- family_docs / family_members / families：仅 `family_members 中存在该 auth.uid()` 的行可 select/upsert；
- personal_docs：`user_id = auth.uid()` 才可读写；
- invites：创建者可写；读取走 Supabase RPC `redeem_invite(short_code)`（服务端校验过期/次数/作废，返回 enc_family_key），避免公开读。

## 6. 同步协议（js/sync.js，纯函数可单测）

### 6.1 同步方向与触发

- 触发时机：启动后、登录/配对后、每次本地写入后 debounce 3s、手动点"立即同步"、网络恢复事件。
- 单向流程：**先推后拉**（push dirty → pull since → 合并）。

### 6.2 打包（push）

1. 扫本地 `_sync='dirty'` 且未删除记录：
   - public/结算/规则 → familyKey 加密 → upsert family_docs（enc_key='family'）；
   - private → personalKey 加密 → family_docs（enc_key='personal', owner_uid=本人）；
   - vault → personalKey 加密 → personal_docs；
   - 删除 → 同表 upsert `deleted=true` 墓碑；
2. 成功后本地标 `_sync='clean'`；失败保留 dirty，下次重试。

### 6.3 拉取与合并（pull，LWW）

1. `pull since = lastPullAt`：拉 family_docs（updatedAt > since）+ personal_docs（本人）；
2. 逐条解密：
   - family 密钥解开 → 正常记录；
   - personal 密钥且 owner 是本人 → 解开（自己的私密/小金库）；
   - personal 密钥但 owner 非本人 → **不解密**，记为"对方私密占位"（仅用于占位计数，不落明文）；
3. 合并规则（纯函数 `mergeRecord(local, remote)`）：
   - 本地无 → 写入（remote.deleted 则直接忽略/物理不存）；
   - 都有 → 比 `updatedAt`，新者胜；相等比 `deviceId` 字典序（确定性 tiebreak）；
   - remote.deleted=true 且较新 → 本地物理删除；
4. 拉取成功更新 lastPullAt。

### 6.4 冲突语义

- 同一笔账两端都改：LWW，后写覆盖先写（记账场景极少：通常只有 owner 改自己的账；结算单仅确认方写）。
- 结算锁定跨设备：结算单是 family_docs，确认后双方拉到 → 锁定状态同步生效（R13 拦截天然跨设备）。
- 金额/分摊等关键字段 LWW 不做字段级合并（v1.1 接受"最后保存为准"，PRD 明示）。

## 7. UI/交互

### 7.1 新增页面/入口

- **登录/注册页**（未登录时替代向导或向导后引导）：邮箱+密码；未登录可进"单机体验"（v1.0 流程，数据不上云）。
- **设置 → 云同步卡片**：
  - 未登录：登录/注册入口；
  - 已登录未建家庭："创建家庭"；
  - 已建家庭未配对："邀请伴侣"（展示邀请链接+短码，可复制/微信分享）、"输入邀请码加入"；
  - 已配对：同步状态（上次同步时间/"同步中…"/"同步失败，点击重试"）、成员列表、"立即同步"按钮、退出登录（保留本地数据提示）。
- 同步状态轻提示：顶部小标题旁小图标（✅已同步 / 🔄同步中 / ⚠️失败），不打断记账。

### 7.2 门控

- 免费版：云同步卡片置灰 + 升级弹层（沿用 applyTier 体系，新增第 9 处入口）；免费版仍可单机使用全部本地功能。
- 身份切换锁（v1.0.1）语义不变：锁的是"本机查看视角切换"；跨设备本来就需要账号密码。

### 8.1 双端验收矩阵（批次⑨/⑩）

| 用例 | 预期 |
|------|------|
| A 记公开账 → 同步 → B 刷新/自动 | B 明细可见，进 B 端结算构成 |

## 9. 风险与降级

| 风险 | 对策 |
|------|------|
| Supabase 免费档限额/停服 | 本地数据永远是主副本（local-first），云只是同步通道；服务不可用时纯单机可用，恢复后补传 |
| 邀请短码（8位）被爆破 | 短码仅辅助、24h 过期、5 次错误作废；主路径用 24 字符链接 secret（~142bit 熵） |
| 忘记登录口令 | 个人密钥备份解不开 → 私密/小金库无法恢复（公开账可由对方设备重新授权恢复 familyKey）；UI 强提示，沿用 v1.0 加密"忘口令不可恢复"原则 |
| 时钟不准导致 LWW 错乱 | updatedAt 用服务器时间校正偏移（同步时取 server time 校准本地差值） |
| supabase-js CDN 失败 | 登录/同步入口提示"云功能加载失败"，单机功能不受影响（脚本 async 加载，不阻塞主应用） |
| 隐私合规 | 服务器零明文是核心卖点：密钥派生/加解密全部在客户端，DDL + RLS 开源可审计 |

## 10. 与 v1.0 的兼容

- v1.0 用户升级后：本地数据原样保留 → 未登录即单机 v1.0 体验；注册登录并建/加入家庭后，schema v2 迁移 + 首次全量同步。
- v1.0 的本地加密锁（crypto.js 整库口令）与 v1.1 云端 E2EE 并存：本地锁管"本机防借用"，云端加密管"服务商不可见"，设置页文案需讲清两层关系（批次⑨处理）。
