## 一、全局说明

### 1.1 产品形态约束

- 纯静态：index.html 单页应用，Tailwind CSS v3（CDN）+ vanilla JS，无构建工具；
- 移动端优先（375px 基准），桌面端自适应（内容区最大宽度 480px 居中，类手机App体验）；
- 底部 Tab 导航 5 项：**明细 / 记一笔（中央大按钮）/ 结算 / 看板 / 设置**。

### 1.2 全局交互规则

| 规则 | 说明 |
|------|------|
| 无注册无登录 | 打开即用；首次进入进入"初始化向导"（见2.4） |
| 金额精度 | 元为单位，支持两位小数；内部计算用分（整数）避免浮点误差，展示时格式化 |
| 空状态 | 每个列表/看板必须有空状态引导（首次记账引导文案） |
| 防误删 | 删除账目需二次确认（confirm弹窗） |
| 措辞规范 | 对外文案用"协作/默契/边界"；禁止"关系修复"类表述；涉及理财的页面固定免责声明"仅供参考，不构成投资建议"（v1.1起涉及） |

### 1.3 角色定义

| 角色 | 说明 |
|------|------|
| 成员A / 成员B | 家庭两位成员（初始化时命名，如"老公/老婆"），各拥有独立小金库账户 |
| 查看人（currentViewer） | 当前操作者身份。v1.0 单设备双人共用，通过"身份切换"模拟两人各自查看；**所有隐私过滤均以查看人身份计算** |

## 二、数据层（批次①）

### 2.1 存储方案

- LocalStorage，统一 key 前缀 `fc_`（finance-couple）；
- `fc_schema_version`：数字版本号，db.js 启动时校验并执行迁移函数（版本不匹配时按迁移链升级）；
- 加密：v1.0 批次⑤提供可选开关（Web Crypto API AES-GCM，口令派生密钥），默认关闭；加密对象为交易与结算数据，设置元数据不加密。

### 2.2 核心数据模型（字段定义）

#### fc_settings（单例）

```js
{
  familyName: "我们的家",            // 展示名
  members: [
    { id: "m1", name: "成员A", emoji: "🧑" },
    { id: "m2", name: "成员B", emoji: "👩" }
  ],
  currentViewer: "m1",               // 当前查看人
  splitRule: {
    defaultRatio: { m1: 50, m2: 50 }, // 默认分摊比例（百分数，和=100）
    categoryOverrides: {}             // { categoryId: { m1: 70, m2: 30 } }
  },
  tier: "family",                     // free | family（商业化模拟开关）
  encryptionEnabled: false,
  createdAt: 0, updatedAt: 0
}
```

#### fc_categories

```js
{ id: "c_food", name: "餐饮", icon: "🍜", type: "expense", builtin: true }
// type: expense | income；预置：餐饮/房租水电/交通/购物/娱乐/医疗/人情/其他 + 收入类（工资/理财收益/其他收入）
```

#### fc_accounts（账户）

```js
{ id: "acc_common", name: "共同账户", type: "shared", ownerId: null }   // 常驻
{ id: "acc_vault_m1", name: "成员A的小金库", type: "vault", ownerId: "m1" } // 常驻，仅owner可见
{ id: "acc_vault_m2", name: "成员B的小金库", type: "vault", ownerId: "m2" }
```

> 小金库账户固定存在且不可删除、不可改名（防止通过改名泄露归属）。v1.0 不做自定义账户（多账户整合属 v1.2）。

#### fc_transactions（交易）

```js
{
  id: "t_xxx",                    // nanoid/时间戳生成
  date: "2026-09-06",
  type: "expense",                // expense | income
  amount: 12800,                  // 单位：分
  categoryId: "c_food",
  ownerId: "m1",                  // 归属人/实付人
  privacy: "public",              // public | private | vault
  vaultId: null,                  // privacy=vault 时必填（acc_vault_m1/m2），且必须=ownerId的小金库
  shared: true,                   // 是否参与共同分摊（expense且public时可为true；private/vault固定false）
  note: "和对象吃火锅",           // ≤50字
  createdAt: 0, updatedAt: 0
}
```

**字段约束（入库校验）**：

1. amount > 0 且 ≤ 99,999,999元；
2. privacy=vault ⇒ vaultId 非空且 vault.ownerId === ownerId；shared 强制 false；
3. privacy=private ⇒ shared 强制 false；
4. income 类型隐私规则同上，但不参与分摊；
5. 删除/编辑需通过 db.js 统一 API，禁止直接操作 localStorage。

#### fc_settlements（结算记录）

```js
{
  id: "s_2026-09",
  month: "2026-09",
  status: "draft",                // draft | confirmed
  transfer: { from: "m2", to: "m1", amount: 32650 },  // 结算方向与金额（分）
  items: [ /* 参与计算的共同支出明细快照 */ ],
  confirmedAt: null               // 确认后锁定，不可再修改当月相关账目（编辑需先作废结算）
}
```

### 2.3 db.js API（约定）

```
fcDb.get(key) / fcDb.set(key, value) / fcDb.remove(key)
fcDb.tx.list(filter) / fcDb.tx.add(data) / fcDb.tx.update(id, patch) / fcDb.tx.remove(id)
fcDb.export() -> JSON string   /  fcDb.import(json) -> { ok, errors }
fcDb.migrate()                  // 启动时自动执行
```

### 2.4 首次初始化向导（3步）

1. 欢迎+隐私承诺说明（"数据只存在这台设备上，不上传任何服务器"）→ 命名家庭；
2. 创建两位成员（名字+emoji头像）；
3. 设置默认分摊比例（默认5:5，可跳过）→ 进入首页。

## 四、记账模块（批次②）

### 4.1 记一笔表单

| 字段 | 控件 | 默认值 | 校验 |
|------|------|--------|------|
| 类型 | 收入/支出 二选一 | 支出 | — |
| 金额 | 数字键盘样式大输入框 | 空 | >0，必填 |
| 分类 | 图标九宫格 | 餐饮（支出）/工资（收入） | 必选 |
| 归属人 | 成员A/B 分段选择器 | 当前查看人 | 必选 |
| 隐私层级 | 三段选择器：公开 / 单笔私密 / 小金库 | 公开 | 见5.x规则 |
| 参与共同分摊 | 开关 | 开（仅public支出显示） | private/vault时隐藏并强制关 |
| 备注 | 文本框 | 空 | ≤50字 |

**提交流程**：校验 → 写入 → 返回明细页并高亮新纪录 → toast"记好啦"。

### 4.2 明细列表

- 按月分组倒序，组头显示当月收入/支出汇总（**按查看人过滤后的口径**）；
- 每条：分类图标、备注、归属人、金额（收入+绿色/支出-正常色）、隐私标识（🔒私密仅本人可见标识；💰小金库标识；公开无标识）；
- 点击条目 → 详情弹层（可编辑/删除；删除二次确认）；
- **私密占位行**：非本人查看时，private 交易显示为一行灰色占位："对方有 1 笔私密记录"（不显示金额/分类/备注），**占位行不参与任何统计**（见5.3）；
- 支持按月份左右切换；支持按分类筛选（仅筛可见数据）。

## 五、三层隐私架构（批次②）

### 5.1 层级定义（核心规则）

| 层级 | privacy值 | 本人（owner）查看 | 对方（另一位成员）查看 |
|------|-----------|------------------|----------------------|
| Layer 1 公开 | public | 完整可见 | 完整可见，参与共同统计与分摊 |
| Layer 2 单笔私密 | private | 完整可见（含🔒标识） | 仅见灰色占位行"对方有1笔私密记录"；**不进任何统计、不分摊** |
| Layer 3 小金库 | vault | 在"我的小金库"视图完整可见；明细列表中以💰标识出现 | **账户不存在**：不显示任何记录、占位行都没有；余额/统计/分摊全部不可见 |

### 5.2 小金库视图（仅本人）

- 入口：明细页顶部"我的小金库"卡片（仅当查看人拥有小金库时显示），显示小金库累计余额与独立明细；
- 小金库交易与普通交易同一张表，以 privacy=vault + vaultId 区分；
- 小金库支出默认为个人支出，**不参与共同分摊**（shared 强制 false）；
- 对方视角：设置页、看板、明细页、结算页**均无小金库任何痕迹**（包括"对方有小金库"的提示也不允许出现）。

### 5.3 统计口径规则（防数据泄露）

| 场景 | 规则 |
|------|------|
| 分类占比 / 双人对比 / 收支汇总 | 只统计"当前查看人可见"的交易：public 全部 + 本人 private/vault；**不含对方 private/vault** |
| 结算计算 | 只用 public 且 shared=true 的支出；private/vault 永不参与 |
| 占位行 | 只提供"有私密记录"的数量提示，不提供任何金额/时间规律信息（列表按时间排序时占位行显示在真实时间位置，但时间精确到日——可接受边界，写入FAQ） |
| 导出 | 当前查看人导出的文件同样按可见性过滤；本人导出含自己全部数据 |

### 5.4 隐私过滤实现要求

- 过滤逻辑集中在 `privacy.js` 纯函数：`visibleTx(transactions, viewerId) -> Tx[]`，所有页面一律调用该函数取数，**禁止页面自行过滤**（保证口径一致、可单测）。

## 六、分摊结算引擎（批次③）

### 6.1 分摊规则

| 规则项 | 说明 |
|--------|------|
| 默认比例 | settings.splitRule.defaultRatio（百分比，校验和=100） |
| 按类别覆盖 | 可为单个分类设置独立比例（如房租 5:5，购物 3:7）；设置页维护，改动**只对新账目生效**，不追溯历史 |
| 参与范围 | 仅 public + shared=true + type=expense 的交易参与分摊 |
| 归属人=实付人 | ownerId 记录"这笔钱谁实际垫付" |

### 6.2 结算算法（月度）

```
对当月每笔共同支出 t：
  shares[m] = t.amount × ratio(m)   （整数分，四舍五入；尾差<分2方按默认比例补齐，保证 Σshares = t.amount）
  paid[m]   += （t.ownerId === m）? t.amount : 0
  balance[m] = paid[m] - shares[m]
结算结果：
  若 balance[m1] > 0 → m2 应付 m1 balance[m1]（双人场景下 balance[m1] === -balance[m2]，取绝对值）
  若为 0 → "本月两清"
```

### 6.3 结算页交互

1. 展示当月"谁应给谁、多少钱"大字卡片（例：**成员B → 成员A：¥326.50**）；
2. "构成明细"折叠列表：每笔共同支出 + 各自分摊额 + 垫付额；
3. 分摊比例修改入口（仅影响新账目提示文案）；
4. **确认结算**按钮 → 写入 fc_settlements（status=confirmed）→ 弹层提示"可在各自记账App中转账，然后在这里标记已结清"；
5. 历史结算页：已确认月份列表；已确认月份的账目被编辑时，提示"该月已结算，修改需先作废本月结算记录"；
6. draft 状态（进入结算页即生成草稿）不锁定账目。

### 6.4 验收用例（必须通过）

| 用例 | 数据 | 期望 |
|------|------|------|
| 基本5:5 | A垫付100元共同餐饮 | B应付A 50元 |
| 自定义比例 | 房租类7000元，比例3:7，A垫付 | B应付A 4900元 |
| 类别覆盖 | 购物200元，覆盖比例8:2，B垫付 | A应付B 40元 |
| 私密不参与 | 一笔private 500元 + 共同支出100元 | 结算只算100元；private不出现在构成明细 |
| 小金库不参与 | vault支出1000元 + 共同支出100元 | 同上，且对方视角完全看不到该笔 |
| 尾差 | 33.33元 5:5 | 两方合计=33.33，单方1667/1666分，差额给m1（默认受益方=实付方优先） |
| 收入不参与 | 工资收入若干 | 结算页金额不受影响 |
| 锁定 | 确认9月结算后编辑9月账目 | 拦截并提示先作废结算 |

## 十、隐私×身份验收矩阵（全版本回归用）

设交易 T：owner=A，privacy=p。

| p \ 查看人 | A（本人） | B（对方） |
|-----------|----------|----------|
| public | 明细完整可见＋统计含T＋分摊含T | 明细完整可见＋统计含T＋分摊含T |
| private | 明细完整可见（🔒）＋统计含T＋不分摊 | 灰色占位行（无金额/分类）＋统计不含＋分摊不含 |
| vault | 小金库视图可见＋明细💰标识＋统计含T | **全程无痕**（无记录/无占位/无余额/无卡片） |

附加断言：

1. 任何页面任何接口取数必须经过 privacy.js（代码审查项）；
2. B 视角导出的文件不含 T（private/vault）；
3. B 视角看板"分类占比"合计 = B 可见交易合计（口径一致性）；
4. 切换身份后 500ms 内完成重渲染（本地数据量 <5000 条）。
